# slime 0.0.1 spec

日期：2026-10-11
状态：待评审

---

## 1. 这个项目是什么

macOS 窗口切换器。参考 [alt-tab-macos](https://github.com/lwouis/alt-tab-macos)，
但加两个它没有的东西：**打字即时搜索**（alt-tab 没有 type-to-search）和**双触发手势**。

0.0.1 的目标是**用最快的速度做出一条能天天用的主链路**，不是做完整产品。

---

## 2. 0.0.1 的验收标准

「能天天用」= 下面 10 条全过：

1. 无 Dock 图标，不出现在系统的 ⌘+Tab 列表里
2. **⌘+Tab**：按住 ⌘ 循环，松手切过去，手感跟系统一致
3. **⌥+Tab**：松手后面板留住，可以直接打字，回车才切
4. 列表含所有 app 的所有窗口（不是只当前 app 的）
5. 打字实时模糊过滤：`ghb` 能命中 `Chrome — GitHub`
6. **⌘+F** 聚焦搜索框（两种模式都要）
7. ↑↓ 和 Tab 移动选中，高亮条平滑滑动
8. 回车 / 松手 → 切过去，**包括最小化的窗口**
9. Esc → 关闭，且不改当前窗口
10. MRU 排序：刚用过的 app 排在最前

## 3. 非目标（0.0.1 明确不做）

| 不做 | 为什么 | 什么时候做 |
|---|---|---|
| 缩略图预览 | 台前调度会把它抓成斜的；还要屏幕录制权限 | 0.0.2，先跑 spike |
| 私有 SkyLight（切窗口不切 Space） | 私有 API，随系统更新失效 | 被这个痛点烦到时 |
| 窗口级 MRU | 要 AXObserver，通知会丢 | 0.0.2 |
| 可配置快捷键 | 先硬编码 | 被某个 app 冲突烦到时 |
| 拼音搜索 | 要带拼音表 | 中文标题多到受不了时 |
| 登录自启 / 打包分发 | 本地跑就够了 | 要给别人的时候 |
| 分层守卫测试 | 纯逻辑层只有 3 个文件 | 纯逻辑层超过 3 个文件时 |
| 横向图标条 | 竖向列表更适合长标题和搜索 | 0.0.2 配缩略图一起 |

**砍掉的东西要留一行说明**：上面每一行都是一次主动放弃，不是遗忘。

## 4. 技术选型：Swift + AppKit

**被否决：Rust。**

这个项目 90% 的难度在 macOS 系统 API，不在语言。一次 ⌘+Tab 的时间分布：

| 步骤 | 谁在干活 | 量级 |
|---|---|---|
| 枚举窗口 `CGWindowListCopyWindowInfo` | WindowServer | 1–3 ms |
| 取窗口标题 `AXUIElementCopyAttributeValue` | 各目标 app | **10–50 ms** |
| 抓缩略图 | WindowServer | 每个几 ms |
| 排序 + 搜索 200 个字符串 | 本地 CPU | **< 0.1 ms** |

热点是跨进程 AX IPC 和 WindowServer，两者都跟语言无关。纯 CPU 部分只占 0.2% ——
就算 Rust 快 10 倍，也是省下 0.05ms。而 `objc2` 手写 FFI 的样板量是 Swift 的 2–3 倍，
且网上每一篇 alt-tab 的踩坑记录都是 Swift 的，换语言等于把坑重踩一遍。

内存同理：大头是 AppKit 对象，换语言省不下十几 MB，用户感知不到。

**存在性证明**：alt-tab-macos 是 Swift 写的，它是瞬时的 —— 天花板由 macOS 定，不由语言定。

**一并排除**：Tauri / egui / winit。它们的窗口做不成 nonactivating panel，
而「切换器自己不能抢焦点」是这个 app 的硬约束。

## 5. 架构

三层，依赖单向：

```
App  ──→  UI  ──→  System  ──→  Core
                               （纯逻辑，不 import AppKit / CoreGraphics）
```

**硬规矩只有一条**：`Core/` 不许 import AppKit / CoreGraphics。
它保住了这个项目里唯一能单测的两块逻辑（`Trigger` 和 `Search`）。

### 文件

```
Sources/slime/
  App/
    main.swift              # NSApplication + .accessory 策略
    AppDelegate.swift       # 组装：权限 → 事件 tap → 缓存 → 面板
    Permission.swift        # 辅助功能权限检查与引导
  Core/                     # 纯逻辑，不 import AppKit / CoreGraphics
    Window.swift            # struct：pid / 窗口 id / app 名 / 标题 / 是否最小化
    Search.swift            # fuzzy 子序列打分 + 过滤排序
    Trigger.swift           # 触发状态机 reduce(state, event) → (state, [Effect])
  System/
    EventTap.swift          # CGEvent ↔ Event，执行 Effect
    WindowEnumerator.swift  # CGWindowList + AX 取标题
    WindowCache.swift       # 快照 + 后台刷新 + 排序
    WindowActivator.swift   # 取消最小化 → kAXRaiseAction → activate
  UI/
    PanelWindow.swift       # NSPanel：nonactivating + 高层级
    PanelController.swift   # 搜索框、列表、键盘、显示/隐藏
Tests/slimeTests/
    TriggerTests.swift
    SearchTests.swift
```

**12 个源文件，零第三方依赖。**

### 主动砍掉的抽象

- **没给 `WindowEnumerator` 抽协议** —— 不会 mock 它，协议是死重量
- **没有配置文件** —— 快捷键硬编码成常量
- **没有依赖注入** —— 只有一个实现，没有第二个
- **没有分层守卫测试** —— 见 §3

## 6. 触发模型

这是本项目最核心的部分。

### 两个手势，两种语义

| 触发 | 松手后 | 按住期间打字 |
|---|---|---|
| **⌘+Tab** | 面板消失，激活高亮项 | 送进搜索框（我们吞掉按键） |
| **⌥+Tab** | **面板留住** | 松手后正常打字，自动进搜索框 |
| 两者 | ⌘+F 聚焦搜索框 | |

⌘+Tab 保肌肉记忆（快速切换），⌥+Tab 给「慢慢找」。
两个手势分开，用户不用在一个手势里猜自己想干嘛。

### 状态机做成纯函数

```swift
// Core/Trigger.swift
func reduce(_ state: State, _ event: Event) -> (State, [Effect])
```

```swift
enum Modifier { case cmd, opt }

enum State {
  case idle
  case armed(Modifier)                                    // 修饰键按下，还没按 Tab
  case holding(Modifier, query: String, selection: Int)   // 面板开着，修饰键按着
  case lingering(query: String, selection: Int)           // ⌥ 模式：修饰键已松开，面板留着
}

enum Event {
  case modifierDown(Modifier), modifierUp(Modifier)
  case tab(shift: Bool)
  case char(Character), backspace, arrow(Int)             // arrow: -1 上 / +1 下
  case focusSearch                                        // ⌘F / ⌥F
  case enter, escape
}

enum Effect {
  case passThrough, swallow
  case showPanel(Mode), hidePanel
  case moveSelection(Int)
  case appendQuery(Character), deleteQueryChar
  case focusSearchField
  case activate, cancel
}
```

**为什么这样切**：把「状态机写错 → 吞掉不该吞的按键 → 全系统键盘挂掉」这个**真实且严重**的风险，
变成可以在单测里穷举的东西。不需要辅助功能权限、不需要 CGEventTap、不需要真人按键。

### 两个事件源，一个状态机

`EventTap` 把 `CGEvent` 翻译成 `Event` 调 `reduce`；`PanelController` 把 `NSEvent` 翻译成
同样的 `Event` 调**同一个** `reduce`。`lingering` 状态下 tap 只无脑放行，键盘走正常 AppKit
响应链 —— 我们最危险的代码，在最不需要工作的时候是关闭的。

### 状态表

| 状态 | 事件 | 新状态 | Effect |
|---|---|---|---|
| idle | ⌘ 按下 | armed(.cmd) | passThrough |
| idle | ⌥ 按下 | armed(.opt) | passThrough |
| armed(m) | Tab | holding(m, "", 0) | swallow, showPanel |
| armed(m) | m 松开 | idle | passThrough |
| armed(m) | 另一个修饰键按下 | armed(m) | passThrough |
| holding(m) | Tab | holding(m, q, sel+1) | swallow, moveSelection(+1) |
| holding(m) | ⇧Tab | holding(m, q, sel−1) | swallow, moveSelection(−1) |
| holding(m) | 字母 c | holding(m, q+c, 0) | swallow, appendQuery(c) |
| holding(m) | 退格 | holding(m, drop-last, 0) | swallow, deleteQueryChar |
| holding(m) | ↑ / ↓ | holding(m, q, sel∓1) | swallow, moveSelection |
| holding(m) | ⌘F / ⌥F | holding(m, q, sel) | swallow, focusSearchField |
| holding(m) | 回车 | idle | swallow, activate, hidePanel |
| holding(m) | Esc | idle | swallow, cancel, hidePanel |
| holding(.cmd) | ⌘ 松开 | idle | activate, hidePanel |
| holding(.opt) | ⌥ 松开 | lingering(q, sel) | focusSearchField |
| holding(m) | **非 m 的修饰键**松开 | holding(m) | passThrough |
| lingering | 任何事件 | 由 PanelController 驱动同上转移 | passThrough（tap 不参与） |
| lingering | ⌘ / ⌥ 按下 | armed(m) | passThrough |

**先按下的修饰键决定模式。** 用户按住 ⌘ 再按 ⌥ 再按 Tab → 走 ⌘ 模式。

## 7. 数据流

**启动**
```
main: NSApplication + .accessory 策略（无 Dock 图标、不进系统 ⌘Tab）
  → 查辅助功能权限 ──没有──→ 弹系统对话框引导 → 退出
  → 装事件 tap
  → 后台首次枚举 → 建快照
  → 订阅 didActivateApplicationNotification（维护 app 级 MRU）
```

**按下 ⌘+Tab / ⌥+Tab**
```
1. 立刻用当前快照渲染面板        ← 瞬时，这是缓存策略的核心
2. 面板成为 key window
3. 后台重新枚举，回来后静默 diff 更新列表（面板已经在了）
```

**打字** → `Search.rank(windows, query)` 在主线程同步跑（< 0.1ms，不搞异步）
→ reload 列表 → 选中回到第 0 行

**回车 / 松手** → 取消最小化 → `kAXRaiseAction` → `NSRunningApplication.activate()`
→ 隐藏面板、清空搜索、更新 MRU

### 窗口缓存策略

按下时才枚举（①）会让第一次按有 ~50ms 卡顿；AXObserver 增量缓存（③）代码最多、
通知会丢、时序难调。

**选中间态（②）**：启动枚举一次；按下时立刻用快照渲染，同时后台重新枚举并静默更新。
用 ① 的代码量拿到接近 ③ 的体感。③ 留到 0.0.2 —— 等真的觉得列表更新不及时了再做，
那时候也更清楚通知在哪些场景会丢。

### 列表内容与排序

**列表不含当前窗口。** 切到自己没有意义，排除掉之后列表就是「能去的地方」，
`index 0` 天然等于「上一个用过的窗口」，与系统 ⌘+Tab 首次 Tab 的选中一致。
（系统是「包含当前窗口 + 首次选中 index 1」，效果相同但模型更绕。）

**匹配目标是 `app名 + " — " + 窗口标题` 的拼接串。** 所以搜 `chrome` 和搜标题片段
命中同一批结果。

**排序**：有 query 时按 fuzzy 得分降序，得分相同按 MRU；无 query 时按 MRU。
（`Search.rank` 是纯函数，这两条都在它的单测里。）

**边界情况**：

| 情况 | 表现 |
|---|---|
| 只有一个窗口（列表为空） | 面板显示「没有其他窗口」，回车和松手都不做事 |
| 后台刷新后列表变短，选中越界 | 选中钳到新的最后一行 |
| 后台刷新后选中项消失 | 选中回到第 0 行 |

## 8. 正确性红线

**这些不是风格问题，是不做就会坏的问题。**

1. **事件 tap 回调里绝对不许阻塞。** 不能有 AX 调用、不能读磁盘、不能等锁 ——
   只有状态机和吞事件。

2. **必须处理 `kCGEventTapDisabledByTimeout`。** 回调超时，macOS 会直接禁掉我们的 tap，
   **那一刻 ⌘+Tab 在全系统范围内失效，直到用户重启 slime**。收到这个事件必须立刻
   `CGEventTapEnable(tap, true)`。

3. **必须有不吞事件的兜底。** tap 被系统连续禁掉几次，就停止吞 ⌘+Tab，退回让系统自己处理，
   并提示用户。**宁可功能失效，不能让用户没法切 app。**

4. **枚举必须在后台线程。** AX 是跨进程同步 IPC，跑主线程 = 按下快捷键就转圈。

5. **过期结果必须丢弃。** 后台枚举还没回来，用户已经 Esc 关掉又重开了 ——
   旧结果不能覆盖新状态。用主线程上的 generation 计数，回来时对不上就扔。

6. **每个 AX element 要设 `AXUIElementSetMessagingTimeout`（~1 秒）。**
   一个无响应的 Electron 应用会让 `AXUIElementCopyAttributeValue` 一直挂着。
   **没有这一条，一个卡死的 app 就能让整个切换器瘫掉。** 超时就退回用 app 名当标题。

7. **窗口过滤按 `kCGWindowLayer == 0`，不按窗口尺寸。** 台前调度搁置的窗口，
   `kCGWindowBounds` 报的是左侧条带里那个又小又斜的方框。按尺寸过滤会把它们全部丢掉，
   而用户完全不知道为什么。**副作用**：它们出现在列表里是**正确**的 —— 激活它们能把窗口
   从条带拉上台。

8. **`Window` 是不可变 struct，快照是不可变数组。** 主线程读旧快照、后台线程造新快照，
   发布时整体替换，**天然无锁**，不碰 `NSLock`，不共享可变状态。

9. **安全输入（密码框）开着时系统不给 tap 发事件** —— 这时 ⌘+Tab 自动走系统原生行为。
   优雅降级，不用写代码，但要知道有这个状态。

## 9. 错误处理

| 情况 | 处理 |
|---|---|
| 没有辅助功能权限 | 启动时 `AXIsProcessTrustedWithOptions` 弹系统对话框引导；**授权后要重启 app 才生效**，所以 UI 上要提示「已授权，请重启 slime」 |
| 事件 tap 建不起来 | 报错并退出，不要静默地在后台运行一个没用的进程 |
| tap 连续被系统禁掉 | 停止吞事件，退回系统原生 ⌘+Tab，通知用户 |
| 单个 app AX 超时 | 该 app 的窗口标题退回用 app 名，其余窗口正常 |
| 权限中途被撤销 | tap 会静默失效；下次触发时检测并重新引导 |

## 13. 工程配置

### 构建

- `Package.swift`，可执行 target `slime`
- **先用 Swift 5 语言模式** —— Swift 6 严格并发会让 AppKit 代码到处要标 `@Sendable`，
  0.0.1 不值当
- `scripts/build-app`：`swift build` + 手工组 `.app` bundle（`Info.plist` 里 `LSUIElement = true`）
- `scripts/test`：`swift test`

### 一个会拖慢迭代的坑，现在就要处理

**辅助功能权限认的是代码签名。** 用 ad-hoc 签名（`codesign -s -`）的话，
每次重新编译二进制哈希都变 → **每次 rebuild 都要重新去系统设置勾一遍权限**。

解法：建一个**自签证书**签这个 app。证书 + bundle id 构成稳定的 designated requirement，
TCC 就认得住了，rebuild 不掉权限。**一次性 10 分钟设置，省掉后面每一次重新授权。**
写进 `scripts/build-app` 的初始化步骤。
