## Goal

Ship a tested 0.0.6 release with a downloadable DMG, reliable window closing, finished panel interactions, the slime identity, and up-to-date documentation.

## Constraints

Use public macOS APIs and no third-party dependencies. Accessibility IPC must remain off the main thread and event-tap callback, with bounded timeouts. Closing must target a freshly identified window, never an application or a guessed foreground window. Preserve the existing permission fallback and keyboard recovery behavior.

Preserve the five-column layout, optional app sections, rounded previews, current-window inclusion, and same-row underline animation from 0.0.5. Cross-row selection places the underline immediately; do not reintroduce the flying line/dot animation.

## 3. Slime identity

Use a fixed sRGB accent of **RGB(150, 215, 106)**, hex **`#96D76A`**. Apply it consistently to the panel selection tint, underline, search focus, and selected settings controls. The settings color picker starts with this color and still allows customization.

On the first launch of 0.0.6, reset all previously saved accent colors to slime green once. The user explicitly confirmed there are no other existing users and requested this reset. Later changes made through the color picker must survive view rebuilding and application restarts; never reset them on every launch.

Use the supplied `/Users/chris/Desktop/slime.png` as the app icon. Store the source in the repository and provide standard macOS icon sizes in the app bundle. Preserve the supplied artwork. The resulting app and the app inside the DMG must display it.

## 4. Command-D: target access and confirmation

Command-D closes the highlighted window without quitting its application. First attempt to close through a safely matched Accessibility close button. Offscreen position alone must not disqualify the target.

When direct access is unavailable because the target is in Stage Manager, minimized, or on another Space:

1. Dismiss the slime panel and end its keyboard session.
2. Bring the target application/window forward using public APIs, then obtain fresh window information.
3. Reconfirm the selected window's identity before issuing its close action. Ambiguous or missing identity must never become a close action against another window.
4. Leave the user in the target application. **Do not automatically reopen or return to the slime panel**, whether closing succeeds, fails, or requires user confirmation.

The user's confirmation refers to any save/close dialog owned by the application; slime does not automatically confirm it or add a confirmation prompt to every ordinary close. If the initial direct close produces such a dialog, reveal the target app and follow the same stay-in-app behavior.

An accepted Accessibility action is not proof of closure. Remove only the target after closure is confirmed. Preserve sibling windows and do not treat temporary absence from Accessibility enumeration as proof that every window of an app has closed. Cancelling a save dialog keeps the window available when the user next summons slime.

If public APIs cannot safely reveal or identify the requested target, do not guess or send an indiscriminate Command-W. Give a clear failure indication where the session remains available; after handing control to the application, keep the panel dismissed. Record unsupported native cases in release acceptance instead of claiming they work.

## 5. Command-D: animation and layout

At the start of closing, quickly fade out the selected card's background tint, window title, and underline, approximately **100 ms**. Only the preview participates in the **500 ms** CRT sequence:

1. Compress vertically into a bright horizontal line.
2. Compress the line horizontally into a point.
3. Flash and extinguish the point.
4. After confirmed closure, remove the target and highlight the next surviving neighbor, or the previous neighbor if no next one remains.

If direct closing fails and the panel remains open, restore the preview, title, selected tint, and underline. Dismissal or a new panel session must not inherit a half-faded card or stale animation.

When confirmed removal changes the number of visible rows, animate the panel to its new height over approximately **200 ms**, preserving its screen-centered placement. Cover both three-to-two and two-to-one row transitions, including grouped layouts. Keep the fixed five-column width. Initial presentation remains immediate; do not add an entrance zoom. The grid, clipping, and glass bounds must stay aligned throughout the resize.

Respect Reduce Motion: use a brief opacity transition instead of CRT compression and place the final panel geometry without animated travel. Correct closure and selection must not depend on animation completion.

## 6. Search appearance and focus

Use a rounded, flat search surface with restrained contrast, consistent spacing, a search icon, and a localized placeholder. Its focused state uses a **2 pt** border at 85% of the chosen accent, plus the accent icon and caret; Command-F must visibly enter that state even when the query is empty.

Preserve the existing interaction model: typing appends to the filter, Backspace removes the last character, arrows and Tab navigate window results, Enter activates the highlighted result, and Escape dismisses the panel. Typing the first character after Command-Tab makes the session persistent, so releasing Command no longer activates a result. Command-F also enters persistent search without typing. Without typing or Command-F, the original hold-Tab-release switching gesture remains.

For this release, the caret represents the end of the filter. As characters are typed or deleted, update its position immediately; do not animate caret travel. Long text must remain clipped inside the field with the text end and caret visible; status messages must not overlap them. Clear focus/caret state on dismissal and a new session.

This is a filter with a visible end caret, not a new full text editor. Arbitrary caret placement, text selection, clipboard editing, and a new input-method integration are outside this request. Keep the event tap as the single owner of keyboard sessions.

## 7. Performance requirements

Added after the design performance review. These requirements constrain the implementation of sections 4–6; timings below are acceptance targets, not measured results.

### Closing latency and cancellation

Use one monotonic deadline for the entire automatic close transaction, starting when Command-D is accepted. The initial budget is **3 seconds**, shared by identification, activation fallback, retries, and closure confirmation. Do not restart the budget when entering the fallback or retrying. Start visual feedback independently of AX completion.

Before every synchronous AX request, check the remaining budget and limit its timeout to the smaller of that budget and the existing one-second per-request limit. Check the deadline between window attributes and enumeration entries, not only between complete snapshots. Once exhausted, issue no further activation or close action, preserve an unconfirmed window, and end the pending UI state. An already executing system call may return late; do not claim that task cancellation forcibly interrupts synchronous IPC. Measure deadline overruns in native acceptance.

Keep fresh identity validation immediately before the destructive action. Never trade this safety check for latency. Closure confirmation should inspect the identified target first; avoid rereading every attribute of every app window on each poll. Use a bounded retry schedule rather than a permanent fixed-rate poll. If a confirmation dialog is positively detected, stop active close retries and hand control to the application; lack of closure alone is not proof of a dialog. User deliberation is outside the automatic transaction budget.

Only one automatic close transaction may be active at a time, including a transaction whose panel has been dismissed. Do not queue repeated Command-D requests. A user cancellation, a replacement session, or disabling slime invalidates pending retries and target activation. Deliberate dismissal for the already-authorized application handoff is different from user cancellation: it may continue that transaction within its original deadline, without reopening the panel. If a close action was already sent, bounded confirmation may still update the cache, but must not send another close action or alter a newer session.

### Background work and cache loading

Coalesce ordinary enumeration requests into **one running refresh and at most one pending refresh**. The pending refresh uses the latest state when it starts. Invalidating a result must also stop obsolete work at safe boundaries; a generation check only at publication is insufficient to prevent backlog.

Read and decode disk thumbnail caches off the main thread. Use the existing memory snapshot or app-icon fallback while loading. Preserve live-window identity checks when publishing loaded images so a late disk result cannot resurrect a removed window or overwrite a newer capture. A missing disk entry must not trigger repeated reads on every unrelated UI update.

The existing thumbnail warm-up wait must remain capped at **300 ms** and must not be extended by repeated refresh requests. Disk loading must not block the main-thread timer that ends this wait. Selection changes, search keystrokes, and animation frames must not request enumeration, screenshot capture, or disk I/O. Actual window refreshes may update thumbnails, retaining existing in-flight deduplication and unavailable-preview fallback.

### Rendering and animation work

Compute the post-close target layout once per logical window-list change. During the height transition, update only the window geometry, clipping, and layout necessary to keep content aligned; do not repeat ranking, window enumeration, thumbnail capture, or card reconstruction on every frame. Reuse cards by window identity. Retarget a resize from its current visible geometry when a newer target arrives; do not enqueue a sequence of obsolete transitions.

CRT takes at most one card-sized preview snapshot per close and animates its layers. Do not capture the desktop, create full-resolution window images, or redraw a screenshot every frame. Remove temporary layers on completion and cancellation.

Typing updates the query and caret promptly. If the ordered result identities have not changed, do not rebuild the grid; update changed metadata only. An unchanged thumbnail must not force a new image wrapper or preview redraw. Combine redundant layout requests within one update. Caret position updates directly without allocating travel animations or recreating focus state on every character. Stop caret blinking and other transient animations when the panel is hidden.

Do not add a search debounce, a general task scheduler, or grid virtualization before measurements justify them. First remove duplicated work and enforce the bounded lifetimes above.

### Measurement and release gates

Use release builds on the target Mac, recording hardware, macOS version, display refresh rate, display arrangement, and Reduce Motion setting. Compare the merged 0.0.5 baseline and 0.0.6 under the same setup. Separate cold disk-cache loading, warm memory-cache operation, and missing-thumbnail fallback.

Exercise **10, 50, and 100 windows**, with grouping on/off, including a dual-display run. Use deterministic fixtures for repeatable ranking/layout measurements and disposable native windows for AX, Stage Manager, Spaces, and visual acceptance. Include an unresponsive application and a save-confirmation dialog. Do not infer native performance from fixtures alone.

Measure input acceptance to the first rendered feedback, not merely how long it takes to enqueue an animation. Record P50/P95 for warm panel presentation, search-result update, and close feedback; separately record automatic-close completion/timeout and frame pacing during CRT and height transitions. Run at least 30 samples per reported interactive-latency scenario and report cold-start samples separately.

Initial release targets are:

- Warm-cache search-result update and initial close feedback: **P95 at most 50 ms** on the recorded target machine, excluding full animation duration and target-app response time.
- Close processing: the shared **3-second** deadline ends automatic retries; slow IPC cannot freeze typing, Escape, or the system application switcher. Record any late return beyond the requested timeout.
- After **20 rapid open/dismiss cycles**, refresh concurrency remains one running plus at most one pending; obsolete work does not accumulate and no obsolete operation activates an app after cancellation.
- Repeated close/open cycles release temporary CRT layers and stop hidden caret animations. Retained task/layer counts must return to their expected idle state; process memory need not immediately return to an identical byte count because caches and allocators can retain storage.
- For 60 Hz and any available higher-refresh display, record frame intervals and identify missed refresh intervals in the resize/CRT runs. Do not treat a 200 ms duration alone as proof of smoothness. Investigate repeated stalls correlated with full-grid updates or I/O before accepting the release.

The latency budgets are provisional until measured, but a missed target is not a pass: optimize or explicitly revise the spec with the measured evidence and rationale before release. Report unavailable hardware scenarios as unverified.

- [ ] Fresh settings use exact sRGB `#96D76A`; an old saved color resets once; a subsequent custom color persists after restart and appears consistently in the panel and settings.
- [ ] The built app and mounted DMG use the supplied icon; bundle version is `0.0.6` / `6` and About agrees.
- [ ] With several windows in one app, Command-D closes only the highlighted one and preserves the others after reopening slime.
- [ ] Verify ordinary, minimized, Stage Manager strip, other-Space, and secondary-display windows using disposable fixtures. Record any case that cannot be safely accessed.
- [ ] On a close requiring application confirmation, the target app becomes available to the user, slime stays dismissed, and both confirm and cancel paths preserve correct window enumeration.
- [ ] During CRT, selection tint, title, and underline fade out; a direct failure restores all of them. Dismissing and reopening during an in-flight close cannot corrupt the new session.
- [ ] Closing from 11 to 10 windows and from 6 to 5 windows animates height without a one-frame jump, clipping errors, or width changes. Repeat with app grouping and Reduce Motion.
- [ ] Command-F in either trigger mode produces an unmistakable focused search state; typing and Backspace position the caret immediately, rapid input does not queue animations, and long queries stay contained.
- [ ] Arrows, Tab, Enter, Escape, Command-comma, and Command-D retain their documented behavior while searching.
- [ ] Both READMEs contain matching usage/release information and tree-formatted structure; module design, decision, and handoff files are in English with historical decisions preserved.
- [ ] `scripts/test`, strict compilation, release build, native acceptance, and mounted DMG verification pass before release.
- [ ] The shared close deadline, cancellation, and single-active-transaction rules hold for slow AX responses, save dialogs, repeated shortcuts, and replacement sessions.
- [ ] Refresh requests coalesce, disk thumbnail loading stays off the main thread, and 20 rapid open/dismiss cycles leave no stale-work backlog.
- [ ] The section 7 release-build measurements are recorded for 10/50/100 windows, with latency targets met or explicitly revised using evidence; no unmeasured claim of smoothness is used as acceptance.
- [ ] After user merge, tag `v0.0.6` points to that merged commit and the published Release includes the verified DMG with a matching checksum.

## Verification boundaries

Use isolated UserDefaults tests for migration, pure trigger/search tests for keyboard behavior, matching tests for target identity, and panel tests for close lifecycle/restoration. Accessibility and WindowServer behavior require native acceptance with disposable windows; unit tests alone cannot certify Stage Manager, Spaces, save dialogs, or visual smoothness. Do not close the user's working documents as test fixtures.

## Non-goals

No automatic updater, dependencies, private WindowServer APIs, application quitting, automatic save-dialog confirmation, new underline flight, or general-purpose text editor. Existing permission degradation remains supported; screen-recording denial must still fall back to app-icon previews.
