# slime 0.0.3 窗口缩略图 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 卡片从 app 图标换成窗口的真实缩略图，同时把玻璃浓度做成可调、高亮线条加粗改色、
面板里 ⌘, 直接开设置、列表按 app 聚拢成相邻。

**Architecture:** 缩略图是新的系统边界 `System/WindowThumbnails.swift`：主线程只持缓存
（`windowID → CGImage`），抓取走 `Task.detached` + ScreenCaptureKit 全在后台（红线 4），
结果回来只收「还在当前快照里」的窗口（红线 5 的意图，用窗口身份而不是计数器表达），
缓存按快照边界整体替换（红线 8）。卡片改成横向给缩略图让位；玻璃浓度是一层遮罩
（`NSGlassEffectView` 没有 opacity，`tintColor` 的 alpha 实测无效）；⌘, 是纯状态机里
多加一个 `Event`/`Effect`；排序聚拢只改 `WindowCache.sort` 里给无名次 app 发号那 4 行。

**Tech Stack:** Swift 6 语言模式 / AppKit / `NSGlassEffectView`(macOS 26) /
ScreenCaptureKit / swift-testing（`import Testing`，不是 XCTest）/ SwiftPM / 零第三方依赖

**Spec:** `docs/specs/2026-10-12-slime-0.0.3-spec.md`。
**执行前先读 spec 的 §4（台前调度 spike 的结论）、§5、§7、§10。**

**测试基线**：开工前 `scripts/test` 是 **81 个测试全绿**。每个任务末尾给了期望的数字 ——

`Sources/slime/System/WindowCache.swift:114-127`，把整段替换成：

```swift
  /// MRU 排序：app 按 MRU 名次，没进过 MRU 的 app 按它在窗口列表里第一次出现的
  /// 位置排在后面；app 内保持 CGWindowList 的 front-to-back 顺序。
  ///
  /// `nonisolated static`（不是 private）是为了 `WindowCacheSortTests` 能直接测。
  /// 4 行的改动不值得为它搬进 `Core/`（CLAUDE.md 第六条「加文件之前先问能不能并进
  /// 已有的那个」）—— 这是对「只有 Core 能单测」的一处有意偏离，见
  /// docs/modules/system/decision.md。
  ///
  /// shortcut: 排序聚拢只保证同一 app 的窗口相邻，不做视觉分组（app 之间加标题 /
  ///           间隔）—— 相邻了还是分不清哪几扇窗属于同一个 app 时再做
  nonisolated static func sort(_ windows: [Window], byMRU mru: [pid_t]) -> [Window] {
    var rank: [pid_t: Int] = [:]
    for (index, pid) in mru.enumerated() { rank[pid] = index }
    // 没名次的 app 也得拿到**不重复**的名次：全给 Int.max 就名次并列，并列退回
    // 窗口列表的 z 序 → 同一个 app 的窗口在列表里交错（冷启动必然如此，
    // mruPids 是空的）。按首现位置依次编号。
    var next = mru.count
    for window in windows where rank[window.pid] == nil {
      rank[window.pid] = next
      next += 1
    }
    // `sorted` 不保证稳定：名次相同的窗口（同一个 app 内）靠原下标定序。
    return windows.enumerated()
      .sorted { a, b in
        let ra = rank[a.element.pid] ?? Int.max
        let rb = rank[b.element.pid] ?? Int.max
        return ra != rb ? ra < rb : a.offset < b.offset
      }
      .map { $0.element }
  }
```

  static let cornerRadiusRange: ClosedRange<Double> = 0...40
  static let defaultCornerRadius: Double = 12

  /// 玻璃浓度（spec §7）：0 = 完全看不到面板后面的内容，1 = 完全透明。
  /// 实数上它是遮罩层的 alpha 的补数（`alpha = 1 − strength`），面板自己换算。
  static let strengthRange: ClosedRange<Double> = 0...1
  /// 默认给偏透明的值，但留出可见余量：1.0 时滑块到底、没有任何变化可看。
  /// shortcut: 0.7 是提案值，对着真机看玻璃定 —— 人工验收清单里那一条。
  static let defaultGlassStrength: Double = 0.7

  /// 高亮线条的颜色（spec §8）。**固定默认值，不跟系统主题色** —— 绑系统意味着
  /// 系统主题一改 slime 就跟着变，那是需求方明确不要的耦合，还多一个「跟随系统」
  /// 勾选框。这个橙是实测过的（近黑面板底 + 2.5pt 线条下对比度够）。
  static let defaultHighlightColor = NSColor(
    srgbRed: 0.969, green: 0.510, blue: 0.106, alpha: 1)

  private let defaults: UserDefaults

  init(defaults: UserDefaults = .standard) {
    self.defaults = defaults
  }

  var glassStyle: GlassStyle {
    get {
      defaults.string(forKey: Key.glassStyle).flatMap(GlassStyle.init(rawValue:)) ?? .regular
    }
    nonmutating set { defaults.set(newValue.rawValue, forKey: Key.glassStyle) }
  }

  /// 读和写都钳位 —— 值可能是旧版本写的、或者被人手动改过。
  var glassStrength: Double {
    get {
      guard defaults.object(forKey: Key.glassStrength) != nil else {
        return Self.defaultGlassStrength
      }
      return Self.clampStrength(defaults.double(forKey: Key.glassStrength))
    }
    nonmutating set {
      defaults.set(Self.clampStrength(newValue), forKey: Key.glassStrength)
    }
  }

  var glassCornerRadius: Double {
    get {
      guard defaults.object(forKey: Key.glassCornerRadius) != nil else {
        return Self.defaultCornerRadius
      }
      return Self.clampCornerRadius(defaults.double(forKey: Key.glassCornerRadius))
    }
    nonmutating set {
      defaults.set(Self.clampCornerRadius(newValue), forKey: Key.glassCornerRadius)
    }
  }

  /// 高亮色不带「无颜色」这个状态（0.0.2 的 `glassTint` 是可选，所以要用
  /// 「取到白就算清除」这种别扭表达）—— 它永远有个值，取不到就用默认。
  var highlightColor: NSColor {
    get {
      guard
        let data = defaults.data(forKey: Key.highlightColor),
        let color = try? NSKeyedUnarchiver.unarchivedObject(ofClass: NSColor.self, from: data)
      else { return Self.defaultHighlightColor }
      return color
    }
    nonmutating set {
      guard
        let data = try? NSKeyedArchiver.archivedData(
          withRootObject: newValue, requiringSecureCoding: true)
      else { return }
      defaults.set(data, forKey: Key.highlightColor)
    }
  }

  static func clampStrength(_ value: Double) -> Double {
    clamp(value, to: strengthRange)
  }

  /// 钳位是这一层唯一的纯逻辑，也是唯一的单测点。
  static func clampCornerRadius(_ value: Double) -> Double {
    clamp(value, to: cornerRadiusRange)
  }

  /// 两个设置项共用的钳位：非有限值按符号取上 / 下界（NaN 落到下界）。
  private static func clamp(_ value: Double, to range: ClosedRange<Double>) -> Double {
    guard value.isFinite else { return value > 0 ? range.upperBound : range.lowerBound }
    return min(max(value, range.lowerBound), range.upperBound)
  }

  private enum Key {
    static let glassStyle = "glass.style"
    static let glassStrength = "glass.strength"
    static let highlightColor = "highlight.color"
    static let glassCornerRadius = "glass.cornerRadius"
  }
}

```swift
import CoreGraphics
import ScreenCaptureKit

/// 窗口缩略图（spec §5）。三件事：按 windowID 缓存、后台抓取、按快照边界清理。
/// **不碰 AppKit 的视图** —— 视图那边只问它要一张图（`image(for:)`）。
///
/// 线程模型：缓存 / `pending` / `live` / `onChange` 全在主线程（`@MainActor`）；
/// 抓图是跨进程 IPC，**全在后台**（红线 4）—— 所以用 `Task.detached` 而不是
/// `Task {}`：后者从 MainActor 上下文继承隔离，等于把 IPC 放回主线程。
///
/// 抓的为什么不是私有 SkyLight 的 `CGSHWCaptureWindowList`（快 ~10ms，还能多抓
/// 一类 Chrome 窗口）：`dlopen` + 零文档 + 每次 macOS 升级赌一次，换 10ms 不值
/// （spec §4.2 / §5.1；CLAUDE.md 第一条第 4 级优先平台原生能力）。
@MainActor
enum WindowThumbnails {
  private static var cache: [UInt32: CGImage] = [:]
  /// 正在飞的窗口 —— 连续两次枚举之间不重复发 IPC。
  private static var pending: Set<UInt32> = []
  /// 当前快照里的窗口（`warm` 每次都重设）。
  private static var live: Set<UInt32> = []

  /// 有新图可显示时的回调（主线程）—— 面板就地把卡片刷新一遍。
  static var onChange: (() -> Void)?

  /// 缩略图的目标宽度（px）：卡片图区 160pt @2x。抓全分辨率是浪费 ——
  /// 一扇 1920×992 的 Chrome 在 2x 下是 30 MB。
  private static let targetPixelWidth = 320.0

  static func image(for window: Window) -> CGImage? { cache[window.windowID] }

  /// 让缓存对齐这份快照：丢掉不在快照里的、补抓还没有的。挂
  /// `WindowCache.onChange`，和 `AppIcons.warm` 同一个钩子 —— 用户第一次按下
  /// ⌘Tab 时缓存已经就绪（spec §5.3 要的「第一帧就是完整的」）。
  static func warm(_ windows: [Window]) {
    live = Set(windows.map(\.windowID))
    // 缓存按快照边界清理（spec §4.5）：窗口关掉就不会再显示 —— 没有任何东西
    // 在渲染它，缓存里也就不该留着。
    //
    // shortcut: 缩略图缓存只按 windowID 存，不做时间戳 / TTL —— 窗口关了就在
    //           快照边界清掉；真的出现过期图误导人时再加时效
    cache = cache.filter { live.contains($0.key) }

    let ids = windows.map(\.windowID).filter { cache[$0] == nil && !pending.contains($0) }
    guard !ids.isEmpty else { return }
    pending.formUnion(ids)

    // `Task.detached` 而不是 `Task {}`：后者在这个 @MainActor 的类型里会继承
    // 主 actor 隔离，抓图就回到主线程了（红线 4）。
    Task.detached(priority: .utility) {
      let captured = await Self.capture(ids)
      await MainActor.run { Self.publish(captured, ids: ids) }
    }
  }

  /// 抓取结束（主线程）：收进缓存。**只收还在快照里的** —— 快照换过之后，
  /// 上一批的窗口可能已经关了，塞回缓存就是「关掉的窗口还在显示」。
  private static func publish(_ captured: [UInt32: CGImage], ids: [UInt32]) {
    pending.subtract(ids)
    let fresh = captured.filter { live.contains($0.key) }
    guard !fresh.isEmpty else { return }
    for (id, image) in fresh { cache[id] = image }
    onChange?()
  }

  // MARK: - 后台（红线 4：这一节不碰主线程状态）

  /// 没权限 / 抓不到都返回空字典 —— 调用方只管「有没有图」。
  private nonisolated static func capture(_ ids: [UInt32]) async -> [UInt32: CGImage] {
    // 没权限就别白跑：每次枚举都去试一遍是无谓的 IPC，SCK 的报错还会刷满日志。
    // 这里用 CoreGraphics 直接问，不走 `App/Permission` —— `System/` 不许依赖
    // `App/`（CLAUDE.md 第六条）；而且对这一个模块它问的是「我能不能干活」，
    // 不是「要不要弹引导文案」（那个在 AppDelegate）。
    guard CGPreflightScreenCaptureAccess() else { return [:] }
    guard
      let content = try? await SCShareableContent.excludingDesktopWindows(
        false, onScreenWindowsOnly: false)
    else { return [:] }

    // 一次枚举只取一遍 SCShareableContent —— 每张都重取的话光这一步就是几百毫秒
    // （spec §13 那条待验证的风险）。
    let byID = Dictionary(
      content.windows.map { ($0.windowID, $0) }, uniquingKeysWith: { first, _ in first })

    return await withTaskGroup(of: (UInt32, CGImage)?.self) { group in
      for id in ids {
        guard let scWindow = byID[id] else { continue }
        group.addTask { await shot(of: scWindow) }  // 并发抓：20 扇窗串行就是 400ms
      }
      var result: [UInt32: CGImage] = [:]
      for await pair in group {
        guard let (id, image) = pair, looksLikeWindowRender(image) else { continue }
        result[id] = image
      }
      return result
    }
  }

  /// 抓一扇窗。抓不到 / 不像窗口渲染都返回 nil（走缓存 → app 图标的降级）。
  private nonisolated static func shot(of scWindow: SCWindow) async -> (UInt32, CGImage)? {
    let frame = scWindow.frame
    guard frame.width > 0, frame.height > 0 else { return nil }
    let config = SCStreamConfiguration()
    config.width = Int(targetPixelWidth)
    config.height = max(1, Int(targetPixelWidth * frame.height / frame.width))
    config.showsCursor = false

    // shortcut: 抓图走 SCK 公开 API，没用私有 SkyLight 的 CGSHWCaptureWindowList
    //           （它快 ~10ms 且能多抓一类 Chrome 窗口）—— 慢到感觉得出来时再说
    guard
      let image = try? await SCScreenshotManager.captureImage(
        contentFilter: SCContentFilter(desktopIndependentWindow: scWindow),
        configuration: config)
    else { return nil }
    return (scWindow.windowID, image)
  }

  /// 抓到的图是不是「像一扇真窗口」。台前调度搁置的窗口在合成层就被渲染成斜的
  /// 透视条带，有些直接是纯白（spec §4.1 实测）。这些图比 app 图标还难认 ——
  /// 丢掉它们，卡片退回缓存图或图标。判据只有两条，各对着一种实测坏法：
  ///
  /// 1. **四角都得不透明** —— 斜条带的四角落在窗口外，是空的。
  /// 2. **至少两种量化后的颜色** —— 「全白」「全黑」这种抓出来的空块只有一种。
  ///
  /// 先缩到 32×32 再采样：判据不该有性能代价。
  ///
  /// shortcut: 判据会误杀「整扇窗只有一个颜色」的窗口（全白的空文档）—— 那时
  ///           退回 app 图标，不是白屏。真的误导人时再细化（spec §14）
  nonisolated static func looksLikeWindowRender(_ image: CGImage) -> Bool {
    let side = 32
    var pixels = [UInt8](repeating: 0, count: side * side * 4)
    // 采样一律走 `buffer`（`bytes`），**不回头读 `pixels`** —— 那是对同一个
    // 数组的重复访问，Swift 的排他性检查会拦。
    return pixels.withUnsafeMutableBytes { buffer -> Bool in
      guard
        let context = CGContext(
          data: buffer.baseAddress, width: side, height: side, bitsPerComponent: 8,
          bytesPerRow: side * 4, space: CGColorSpaceCreateDeviceRGB(),
          bitmapInfo: CGImageAlphaInfo.premultipliedLast.rawValue)
      else { return true }  // 建不出上下文就别拦着：宁可显示一张图，不要白屏
      context.draw(image, in: CGRect(x: 0, y: 0, width: side, height: side))
      let bytes = buffer.bindMemory(to: UInt8.self)

      for (x, y) in [(0, 0), (side - 1, 0), (0, side - 1), (side - 1, side - 1)]
      where bytes[(y * side + x) * 4 + 3] < 250 {
        return false
      }

      // 每通道取高 4 位做桶：抗抖动 / 抗压缩噪声，同时「纯色」还是只有一个桶。
      var seen: Set<UInt32> = []
      for index in stride(from: 0, to: bytes.count, by: 4) {
        let key =
          UInt32(bytes[index] >> 4) << 8 | UInt32(bytes[index + 1] >> 4) << 4
          | UInt32(bytes[index + 2] >> 4)
        seen.insert(key)
        if seen.count >= 2 { return true }
      }
      return false
    }
  }
}
```

## 2026-10-12 · 缩略图抓取：SCK 公开 API，不用私有 SkyLight

- **背景**：spec §4 的 spike。私有 `CGSHWCaptureWindowList` 比 SCK 快 ~10ms，

  没有任何公开签名，参数猜错有把 WindowServer 搞崩的风险）。

- **推翻条件**：SCK 在真实使用里经常抓不到正常窗口（那时重估私有路径），

## 2026-10-12 · 过期缩略图用窗口身份判，不用 generation 计数

- **背景**：红线 5 要求「过期结果必须丢弃」。`WindowCache` 用的是 generation 计数。
- **选定**：`WindowThumbnails` 用 `live: Set<UInt32>`（当前快照的 windowID 集合），
  抓取结果回来时只收 `live` 里的。
- **为什么**：计数器只能说「这批可能过期了」，身份能说「这扇窗已经不在快照里了」。
  而且计数器在这里有个洞：批次 A 被批次 B 顶掉时，B 看到 A 的窗口还在 pending
  就跳过，A 回来又因 generation 不符而丢弃并清掉 pending —— 那几个窗口再没人抓。
- **代价**：windowID 被 WindowServer 复用时会认错（每一次快照边界都清理，
  所以复用得跨过边界才可能撞上）。
- **推翻条件**：出现「关掉的窗口的图被显示出来」的实测案例。

- **代价**：**这是对「只有 Core 能单测」的一处有意偏离** —— `System/` 里出现了一个
