# slime 0.1.0：中文输入与搜索编辑

- **状态**：版本范围已确认；交互细则待评审，尚未实现。
- **相关 issue**：[#102](https://github.com/chriscco/slime/issues/102)。
- **交付方式**：spec 与实现共用分支及 PR，不单独合并 spec。

## 目标

用户可以用中文输入法输入应用名或窗口标题，通过正常的文本编辑修正查询，再准确切换到搜索结果。0.1.0 聚焦「输入—找到—切换」。

## 非目标

- 拼音、首字母、简繁转换及别名搜索：本版只匹配提交的文字；根据后续使用反馈另立需求。
- 搜索打分、MRU、分组、窗口枚举和激活策略调整：沿用现有行为，避免把输入问题和排序、窗口发现问题混在一起。
- 输入法管理、自动切换中英文、新快捷键配置、搜索历史：复用用户当前输入法和系统编辑能力；有明确需求后再考虑。
- 全部第三方输入法的兼容承诺：以系统简体拼音和一种实际安装的第三方中文输入法验收，记录具体版本。

## 背景与约束

目前 `PanelContentView` 位于 `PanelWindow.swift`，搜索区由不可编辑的 `NSTextField` 标签和模拟光标组成。`EventTap` 读取按键字符，`Trigger` 产生追加或删除字符的 effect，`PanelController` 再维护查询。该路径没有完整的组词、选区和文本替换语义。

`Search.rank` 已按 Swift `Character` 匹配窗口 label，可复用来匹配提交后的中文；本版不改变其排序规则。

保留非激活式面板、双触发手势、现有权限要求和最低系统版本。输入实现不得引入运行时依赖或要求激活 slime 为普通前台应用。若原生文本编辑与现有面板焦点模型有冲突，应先验证并修订方案，不能静默更改产品行为。

## 交互方案

### 进入搜索与结果导航

区分窗口导航和文本编辑，由输入法组词拥有最高的文本按键优先级：

- 按住 `⌘` 连按 `Tab` 时保持窗口导航；未进入搜索时，松开 `⌘` 立即切换。
- `⌥Tab` 松开 `⌥` 后进入搜索编辑；`⌘F` 或点击搜索框也进入编辑。
- 导航中直接打字进入编辑，首个字符不得丢失或重复。进入后松开触发修饰键不再切换，回车才确认。
- 沿用按住触发键直接打字的便利入口：原有普通字母输入仍可形成查询并留住面板。完整中文组词在松开触发键后进行；不要求把带 `⌘` 的字母解释为中文组合输入。
- `⌘F` 聚焦时保留已有查询和选区；首次进入放在末尾，不自动全选。点击搜索框按点击位置定位光标。
- 清空查询恢复全部结果，但保持编辑状态，不恢复松键自动切换。

| 按键 | 窗口导航 | 文本编辑、未组词 | 正在组词或处理候选词 |
|---|---|---|---|
| `←` / `→` | 左右移动窗口选中 | 移动文本光标，组合修饰键沿用系统编辑语义 | 交给输入法 |
| `↑` / `↓` | 上下移动窗口选中 | 上下移动窗口选中，保留编辑焦点 | 交给输入法 |
| `Tab` / `⇧Tab` | 前后选择窗口 | 前后选择窗口，保留编辑焦点 | 先交给输入法，不同时移动窗口 |
| 数字、空格 | 普通文本进入搜索 | 插入文字 | 交给输入法选词或输入 |
| `Enter` | 切换选中窗口 | 切换选中窗口 | 仅由输入法处理；同一次按键不得切换窗口 |
| `Esc` | 取消面板 | 取消面板，不先清空查询 | 取消本次组合输入、保留已提交查询；后续一次 `Esc` 才取消面板 |
| `Backspace` | 保持现有查询删除行为 | 删除选区或光标前字符 | 交给输入法编辑组合内容 |

这是明确的兼容性调整：编辑状态下左右键改为文本光标移动；结果仍可通过 Tab 和上下键选择。文档和快捷键说明必须同步说明。

### 组合输入与查询提交

- 组合文字与候选窗由原生输入系统显示，候选窗应跟随真实插入点，不手写拼音转换或候选 UI。
- 正在组词时，过滤继续使用上一次已提交的完整查询。组合文字变化不触发重新排序，也不重置窗口选中。
- 一次提交可以包含多个字符或替换选区。提交后以编辑器的完整文本更新查询，不能逐键猜测新增或删除了哪些字。
- 取消组合输入恢复其开始前的已提交文本；没有新查询就不重新过滤。
- 普通英文输入、删除、剪切、粘贴在文本变更后立即过滤；只有查询确实变化时才重置选中到首项。
- 后台窗口或预览刷新不能覆盖正在编辑的文字、选区或组合状态。组合期间窗口集合变化仍可按已提交查询刷新结果。
- 无结果时回车不激活任何窗口；保留现有结束面板会话的行为。

### 常规编辑与面板命令

- 支持鼠标定位和选择、`⇧` 加方向键扩选、`⌘A/C/X/V`、删除选区、光标前删除和系统支持的光标后删除。
- 采用原生单行文本编辑语义；中文、英文、标点、emoji 混合输入及粘贴不丢失字符。多行粘贴的换行归一为空格，不触发窗口切换。
- 选区替换、粘贴和剪切均以最终完整文本过滤；组合状态下的编辑命令由输入系统先处理。
- 保留 `⌘D` 关闭选中窗口和 `⌘,` 打开设置。组合期间暂停这两个面板命令，防止选词时误关闭窗口或离开输入；不把它们转成查询字母。
- 未绑定的 Command 组合不再把字母拼进查询，交由当前编辑器的标准命令处理；不得泄漏给面板后方应用。
- 保留已有 Option 触发方式与显式快捷键入口；进入编辑后的 Option 文本编辑组合交给原生编辑器，不再统一剥掉 Option。
- 不主动改写系统输入源。切换输入法时面板保留，组合内容按输入法自身的提交或取消结果同步。
- 搜索框暴露真实文本值、选区和编辑能力给辅助功能；主题、高亮色、占位提示及长文本光标可见性保持可用。

### 关闭、焦点与会话边界

- 候选窗出现和选词不应被误判为用户离开面板。
- `Esc` 取消面板不激活任何结果，原应用继续接收输入；选中窗口后由既有激活流程接管焦点。
- 用户点击其他应用时面板关闭，未提交组合内容丢弃，不写入原应用或下一次面板会话。
- 每次打开重新开始空查询、无组合状态的会话；旧会话的异步文字或按键回调不得修改新会话。
- 关闭窗口动画期间保留现有输入保护，结束后恢复可编辑状态；不能残留旧选区或候选窗。

## 模块责任与实现边界

优先使用 AppKit 原生可编辑文本控件及其编辑器，替换标签和模拟光标。保留现有搜索行布局，不新建通用输入框框架。

| 位置 | 本版责任 |
|---|---|
| `UI/PanelWindow.swift` 内的 `PanelContentView` | 原生编辑控件、真实焦点、选区、组合状态、编辑命令及可访问性；删除被替代的模拟编辑代码 |
| `UI/PanelController.swift` | 处理完整查询变更，刷新结果与选中；维护面板会话、输入焦点和取消边界 |
| `System/EventTap.swift` 内的 `KeyTable` / `EventTap` | 全局触发手势与输入交接；编辑期间不能提前吞掉输入法需要的事件 |
| `Core/Trigger.swift` | 用纯状态和事件表达搜索开始、完整查询变更及面板命令；不引入 AppKit 或输入法对象 |
| `App/AppDelegate.swift` | 连接必要回调与会话取消，沿用现有生命周期 |
| `Core/Search.swift` | 复用现有匹配和排序，以中文及混合文字测试验证 |

全局触发仍只有一个负责人；文本编辑只由原生编辑器解释一次。不得让 tap 和 AppKit 同时运行一份面板状态机，造成重复移动或激活。

交接至少区分「进入搜索」和「提交完整查询」：开始组词即应解除松开 `⌘` 自动激活，不能等汉字提交后再切换状态。查询应有单一更新路径，避免继续在 Trigger 和 Controller 各自追加字符。

事件 tap 回调不得访问 UI、等待主线程、调用 AX 或执行 I/O。跨线程消息沿用现有会话失效机制；吞键必须保持 keyDown/keyUp 配对。交接完成前的首键、紧随其后的修饰键释放以及快速取消必须专门验证，不能依赖队列“通常足够快”。

保留 tap 超时恢复、连续失败降级、禁用后原生 `⌘Tab` 以及 Secure Input 下的既有退化。异常时不能持续吞掉其他应用的键盘输入。

取舍：原生编辑会改变编辑状态下左右键和未绑定 Command 组合的旧行为，但带来完整的输入法、选区与粘贴语义。继续扩展逐键字符拼接无法覆盖这些需求；自实现输入法客户端增加不必要的组合文本和候选窗维护成本。

## 验收标准

### 自动化

沿用 `swift-testing` 和现有测试入口，行为实现前先添加失败测试：

1. `TriggerTests`：两种触发方式、开始搜索后松键不激活、完整查询替换、清空后保留编辑状态、取消及关闭窗口流程。
2. `KeyTableTests` / `EventTapTests`：编辑事件交接、组合确认不同时触发面板命令、未知 Command 不转字符、首键只处理一次、吞键配对、快速取消后的旧事件失效、禁用与降级放行。
3. `SearchTests`：中文查询、中文与英文混合、空查询及同分 MRU 顺序不变。
4. 现有面板测试及可测试的编辑边界：多字符提交、选区替换、粘贴、取消组合、重复文本通知不重置选择；不得仅验证字符串追加这一条理想路径。
5. 运行 `scripts/test` 和 release 构建。模拟事件通过不能替代输入法桌面验收。

### 桌面验收

记录 macOS、输入法名称与版本、触发方式、复现步骤和结果。两种触发方式都覆盖系统简体拼音；一种第三方输入法至少覆盖下列 1–4、8 项。未完成第三方验证须明确列为发行前未完成项。

| # | 场景与操作 | 通过条件 |
|---|---|---|
| 1 | 搜索框输入拼音，翻页选词，以数字、空格或回车确认 | 候选窗位于插入点附近；选择过程不移动窗口选中；确认得到汉字，不切走面板 |
| 2 | 已提交“工作”，继续组词再按 `Esc`，随后再按 `Esc` | 第一次保留“工作”和面板；第二次关闭面板，原窗口未被切换 |
| 3 | 输入中英文混合查询，移动光标、扩选、替换、删除 | 搜索文本和过滤结果一致，无重复字符、残留拼音或截断 |
| 4 | `⌘A` 后粘贴中文、emoji 及含换行文本 | 替换整个查询，换行变空格；不触发激活，后方应用未收到输入 |
| 5 | `⌘Tab` 后直接打字或 `⌘F`，立即松开 `⌘` | 面板保留；首字符不丢失、不重复；随后可进行中文输入 |
| 6 | 纯 `⌘Tab` 循环并松键；`⌥Tab` 松键后输入 | 前者按既有规则切换，后者保持面板并能编辑 |
| 7 | 编辑时用左右键修正查询，再用 Tab / 上下键选结果并回车 | 光标编辑和结果导航不冲突；只激活最终选中的窗口 |
| 8 | 候选窗出现、点击候选词、切换输入源，再点击其他应用 | 选词与切换输入源不误关闭面板；点击其他应用关闭面板，无文字泄漏 |
| 9 | 组词中后台刷新窗口或预览；关闭后立即重新打开 | 组合文字和选区不被刷新覆盖；新会话为空，旧回调不回填 |
| 10 | 组词时按 `⌘D` / `⌘,`；结束组词后再次执行 | 组词时不关闭窗口或打开设置；结束后既有命令可用 |
| 11 | 无匹配时回车、清空查询、重复打开关闭、长文本编辑 | 不激活错误窗口；空查询恢复列表；无遗留候选窗，光标始终可见 |
| 12 | 禁用 slime、触发 tap 退化或使用 Secure Input 场景 | 原生切换与其他应用键盘可用；无持续吞键或卡住修饰键 |

至少在当前开发系统完成实测，并记录 macOS 15 兼容验证是否完成；未经实测不得扩大对最低版本或第三方输入法的支持承诺。
