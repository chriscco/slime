# slime 0.0.2 spec — 卡片网格 / 液态玻璃 / 设置页

- **状态**：已实现
- **相关 issue**：待建
- **相关 PR**：待建

## 1. 这个 spec 要做什么

0.0.1 的面板是**竖向列表**（行高 26px 的文字行 + 一条滑动高亮）。0.0.2 把它换成
**卡片网格**：水平排列、一排最多 5 张、超出换行、每张卡是 app 图标 + 下方窗口名。
顺带三件事：面板换成可调的液态玻璃、加一个设置页、切片时加平滑动画。

**这不是给列表换皮，是重写 `UI/PanelWindow` 的展示层。** `docs/modules/panel/decision.md`
里那条「不用 NSTableView，手动布局」的**推翻条件**写的就是这一刻：

> 推翻条件：列表要加上缩略图 / 图标（0.0.2）时重新评估。

按规矩追加新条目并链接回旧条目，不删旧的。

---

## 2. 验收标准

1. 面板显示为卡片网格，**一排最多 5 张**，第 6 张换到第二排
2. 每张卡：app 图标在上，窗口名在下（名字过长截断）
3. 卡数少于 5 时**面板宽度跟着收窄**，不留空格子
4. 面板是液态玻璃，且**圆心角 / 样式 / 色调可以在设置页里调，改完立刻生效**
5. **Tab / ⇧Tab** 在卡片间前后移动，跨行时按阅读顺序
6. **← / →** 左右移动一格，**↑ / ↓** 上下移动一排
   （顺带修掉现存 bug：现在按 ← / → 会往搜索框塞不可见字符、列表被清空）
7. 移动时有平滑动画；**跨行超过一排的移动不动画**（否则高亮斜穿整个面板）
8. 菜单栏有 slime 图标，菜单里能打开设置、能退出
9. 设置窗口里改玻璃参数，重新唤出面板后是新样式
10. 0.0.1 的 10 条验收全部仍然通过（尤其：打字搜索、⌘F、MRU、最小化窗口、台前调度窗口）

## 3. 非目标

| 不做 | 为什么 | 什么时候做 |
|---|---|---|
| **真截图缩略图** | 台前调度会把搁置的窗口抓成斜的，那个 spike 还没跑 | 0.0.2 之后，先跑 spike |
| 每张卡片单独做玻璃 | 只有一块玻璃面就够；多面要配 `NSGlassEffectContainerView` 合并渲染 | 视觉上真的需要时 |
| 鼠标点选卡片 | 0.0.1 就非目标；键盘主链路没跑顺之前不加 | 被缺它烦到时 |
| 每排窗口数可调 | 设置页只放玻璃调节（用户定的范围） | 5 张真的不够用时 |
| 动画时长 / 开关可调 | 同上 | 手感被抱怨时 |
| 主题（浅 / 深切换） | 跟随系统 | 有人要时 |
| 快捷键自定义 | **0.0.1 spec §3 已显式推迟**（「被某个 app 冲突烦到时」），现在做会推翻那条记录 | 被冲突烦到时 |
| 面板搜索框的输入法（IME）支持 | 见 `docs/modules/panel/decision.md` 的「搜索框是只读展示」条目 —— 打不进中文查询。**这是面板的问题，不是设置页的**（设置页只有分段控件 / 色板 / 滑块，没有文本输入） | 做拼音搜索时 |

**「窗口预览」在本 spec 里 = app 图标卡片，不是窗口截图。** 两者常被混为一谈，
但截图那条路要屏幕录制权限 + 台前调度 spike，是独立的一次改造。

## 4. 平台底线：`.macOS(.v14)` → `.macOS(.v26)`

`NSGlassEffectView` 是 `API_AVAILABLE(macos(26.0))`（SDK 里确认过）。

**提到 26，不做 `NSVisualEffectView` 兜底分支。**

理由：CI 跑的是 `macos-26-arm64`，开发机是 macOS 27。写一个回退分支意味着
**一段永远没人能执行的代码** —— 没有 macOS 14 的机器可以验证它，它只会在半年后
变成一个没人敢删的黑盒。宁可让底线诚实地写 26。

**代价**：slime 从此不支持 macOS 14/15。这是有意的，推翻条件是「真的有 26 以下的用户」。

> 实现细节：`PackageDescription` 里可能得写 `.macOS("26.0")` 字符串形式而不是 `.v26`
> 枚举。编译期就能撞出来。

## 5. 卡片网格

### 5.1 把网格数学抠进 `Core/GridLayout.swift`

现在是竖向列表，高度就是一乘一加；网格要算列数、行数、换行、最后一行不满、
以及「第 n 张卡在哪」—— **off-by-one 全藏在这里，而且只能靠肉眼发现**。

```swift
// Core/ —— 只用 Swift 基本类型。CGSize / NSRect 是 CoreGraphics 的，这一层不许碰
// （CLAUDE.md 第六条；Window.swift 用 UInt32 而不是 CGWindowID 是同一个理由）。
public struct GridLayout: Equatable {
  public static let maxColumns = 5
  public let count: Int
  public let columns: Int
  public let rows: Int
  public let visibleRows: Int      // min(rows, maxVisibleRows)
  public let panelWidth: Double
  public let panelHeight: Double   // 含头部（搜索框）
  public func origin(of index: Int) -> (x: Double, y: Double)
  public func shouldAnimate(from: Int, to: Int) -> Bool
}
```

**计算式**（写进 spec 是为了让验收可证伪，不是实现指令）：

```
columns     = min(count, maxColumns)
rows        = ceil(count / maxColumns)
visibleRows = min(rows, maxVisibleRows)

panelWidth  = 2*padding + columns*cardWidth + max(0, columns-1)*gap
panelHeight = 2*padding + headerHeight + visibleRows*cardHeight + max(0, visibleRows-1)*gap
              ↑ 两个 max(0, …) 不是防御性编程：count == 0 时 columns/visibleRows 都是 0，
                少写一个就会算出 (0-1)*gap = -12，面板比空态文字还窄

col(i) = i % columns          -- columns 对整张表是常量，所以取模成立
row(i) = i / columns
origin(i) = ( padding + col(i)*(cardWidth+gap),
              padding + headerHeight + row(i)*(cardHeight+gap) )
```

**默认常量**：`cardWidth 112`、`cardHeight 92`（图标 64 + 间隙 6 + 文字 18 + 内边距）、
`gap 12`、`padding 12`、`headerHeight 34 + 12`、`maxVisibleRows 3`。
5 列时面板宽 = `24 + 560 + 48 = 632`，跟现在的 640 基本一致。

**边界**：`count == 0` → columns/rows = 0，面板只剩头部 + 空态文字。

### 5.2 这会触发 CLAUDE.md 里已经写好的那条规则

> 分层守卫测试 | `Core/` 超过 3 个文件时（现在 3 个，到第 4 个就补）

加 `GridLayout.swift` 就是第 4 个 → **欠一个「拦 AppKit import」的守卫测试**。
规则是当初自己定的，现在该还。

## 6. 方向键的轴语义（★ 这一节动 `Core/Trigger`）

### 问题

现状：`Event.arrow(Int)` **只有垂直**（`-1` 上 / `+1` 下），`KeyTable` 只映射了
`↑`(126) / `↓`(125)。**`←`(123) / `→`(124) 掉进 `default` 分支。**

而方向键的 `charactersIgnoringModifiers` 是私用区的 `U+F702` / `U+F703` ——
既不是控制字符（`isControlLike` 判的是 `< 0x20 || == 0x7F`），也不为 nil，
于是被翻译成 `.char("\u{F702}")`。

**这是一个现存的 bug，不是「左右键是死的」**：面板里按 ← 或 → 会往搜索框塞一个
看不见的字符，列表随即被过滤成空 —— 看起来像「面板突然什么都没有了」。
竖向列表里没人会去按左右键，所以从没暴露。

网格里还有第二个错：↑ 若仍是 `moveSelection(-1)`，按一下只横着挪一格，而不是换行。
而 `Effect.moveSelection(Int)` 只带裸 delta，**面板层无从得知这个位移是
「一行」还是「一格」**。

### 方案

```swift
public enum Axis: Equatable, Sendable { case horizontal, vertical }

// Event：模型化「用户按了哪个键」，不预判语义
case arrow(axis: Axis, step: Int)

// Effect：把「一行」翻译成「几格」是布局的活，留给面板层
case moveSelection(axis: Axis, step: Int)
```

`Trigger` 保持纯净（**不知道网格有几列**）；`PanelController` 做：

```swift
let delta = axis == .vertical ? layout.columns : 1
selection = (selection + step * delta + rows.count) % rows.count
```

**为什么不是把列数传给 Trigger**：那会让纯状态机依赖布局状态 —— 改一次列数就得
重建状态机，而且 `TriggerTests` 要开始构造布局。轴语义是纯粹的输入描述，
列数是纯粹的布局知识，两者不该见面。

### 连带改动

| 文件 | 改什么 |
|---|---|
| `Core/Trigger.swift` | `Event.arrow` 加轴；`Effect.moveSelection` 加轴；`panelStep` 透传 |
| `System/EventTap.swift` | `KeyTable` 加 123/124；126/125 带上 `axis: .vertical` |
| `UI/PanelWindow.swift` | 无（它复用 `KeyTable`） |
| `Tests/slimeTests/TriggerTests.swift` | 3 处 arrow 断言（L72 / L117 / L120） |

**注意 `Trigger` 自己的 `selection` 是无界步数计数**（见 `Trigger.swift` 的注释），
显示选中以 `PanelController` 为准 —— 这个改动不改变那个契约，只是给步数标上轴。

## 7. 液态玻璃

`NSGlassEffectView` 包住面板内容，可调参数就是它的三个属性：`style`
（`.regular` / `.clear`）、`tintColor`、`cornerRadius`。

### 一个必须遵守的 API 约束

头文件里明说：

> `NSGlassEffectView` only guarantees the `contentView` will be placed inside the
> glass effect; arbitrary subviews aren't guaranteed specific behavior with regard
> to z-order in relation to the content view or glass effect.

**所以搜索框、网格、空态标签必须全部塞进 `glassView.contentView`**，
不能当玻璃视图的兄弟节点。这条不遵守的症状是「子视图的层级随机错乱」，
而且不一定每次都复现。

### 窗口要改的地方

- `isOpaque = false`、`backgroundColor = .clear`（现在已经是）
- **删掉 `content.layer.cornerRadius = 12`** —— 圆角归玻璃视图的 `cornerRadius` 管
- `contentRect` 初值 640×160 要跟着网格尺寸走

### 顺手砍掉

`NSGlassEffectContainerView`（合并邻近玻璃省渲染）—— 我们只有**一块**玻璃面。
名字记着，将来每张卡片单独做玻璃时再回来。

## 8. 设置页面

### 入口：菜单栏图标

现在 app 是 `.accessory`（无 Dock 图标、无菜单栏项），**没有任何打开设置的路径**。
加 `NSStatusItem`：菜单两项 ——「设置…」「退出 slime」。

**这是 spec2 的隐含交付物**，需求 3 只说了「加入设置页面」，但不说入口的话
设置页做出来打不开。

### 设置窗口

`NSWindow`（titled + closable），三个控件：

| 控件 | 类型 | 取值 |
|---|---|---|
| 玻璃样式 | `NSSegmentedControl` | Regular / Clear |
| 色调 | `NSColorWell` | 任意颜色（含「无色调」） |
| 圆角 | `NSSlider` | 0 – 40，默认 12 |

从 `.accessory` app 打开普通窗口要先 `NSApp.activate()`，否则窗口在别的 app 后面。

### 存储：`System/Settings.swift`

`UserDefaults` 的类型化封装。**放 `System/` 不放 `Core/`** —— 读写全局可变状态是副作用，
不是纯逻辑，`Core/` 的禁令（CLAUDE.md 第六条）不让它进。

```swift
struct Settings {
  init(defaults: UserDefaults = .standard)   // 注入是为了测试不污染真 defaults
  var glassStyle: GlassStyle { get set }
  var glassTint: NSColor? { get set }
  var glassCornerRadius: Double { get set }  // set 时钳位到 0...40
}
```

### 面板什么时候读设置

**`show()` 时读，不做观察者。** 省掉一整套通知机制 —— 设置窗口一旦成为 key，
面板就 `resignKey` 藏起来了，所以「面板开着时改设置」这个场景**根本不存在**。
（§11 验收第 9 条写的是「重新唤出面板后是新样式」，就是这个意思。）

## 9. 图标

`NSRunningApplication(processIdentifier:)` → `bundleURL` → `NSWorkspace.icon(forFile:)`，
按 **bundle id** 缓存（同一 app 的多个窗口共用一张图标；取图标不便宜）。

### 坑：必须在主线程预热

取图标是主线程 API，但枚举在后台线程（红线 4）。如果等第一次按快捷键才去取，
**N 个窗口 × 每次几毫秒全砸在主线程上** —— 0.0.1 spec §7 承诺的「按下即出面板」
当场作废。

**解法：启动时那次枚举完成后，顺手在主线程把图标缓存预热掉。**
快捷键路径上只读缓存，一次都不取。

> 待确认：现在的 `WindowEnumerator` 有没有「枚举完成」的回调可以挂。没有的话
> 要加一个 —— 这会让 spec2 多碰一处 `System/` 层代码。

### 分层

**图标不挂进 `Core/Window`。** `Window` 是纯值类型，不许 import AppKit。
图标由 UI 层按 `pid` 现查缓存，`AppIcons` 放 `System/`。

## 10. 动画

卡片尺寸统一，所以高亮是**一个恒定大小的圆角矩形在平移** —— 比列表还简单
（列表时宽度要跟着 `bounds` 走）。

- 时长从现在的 `0.09` 提到 **`0.15`，缓动用 ease-out**
- 高亮是网格视图 `positioned: .below` 的子视图（沿用现在的做法）

### 什么时候不动画

高亮**跨行超过一排**时会斜穿整个面板，看起来像坏了。两种情况都会：

- Tab 从最后一张卡绕回第一张（20 张卡时是第 3 排 → 第 0 排）
- **↑ 在第一排时往上走** → 绕到最后一排（index 2 → 17）

只判「首尾回绕」会漏掉第二种（`|17−2| = 15 ≠ count−1 = 19`）。**按行距判，一条规则覆盖全部**：

```swift
/// 位移没跨行、或只跨一排 → 动画；跨更多排 → 直接跳。
func shouldAnimate(from: Int, to: Int) -> Bool {
  guard count > 0, rows > 1 else { return true }   // 单排表：横向滑动本来就好看
  let dr = abs((to / columns) - (from / columns))
  return dr <= 1
}
```

单排表（`count <= maxColumns`）**永远返回 true** —— 那一行的首尾回绕是纯横向滑动，
看着是自然的，不需要特判。
