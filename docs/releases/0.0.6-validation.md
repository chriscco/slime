## Disposable native checks

Four independent AppKit windows were used; automatic window tabbing was disabled so four tabs could not be mistaken for four windows. No working user document was closed.

- Target window 2 was initially inaccessible through AX while sibling window 4 was exposed. Initial close returned `unavailable`; public activation/AXFrontmost/raise plus fresh identification closed window 2 in **1.282 s**, with windows 1, 3, and 4 still present in AX and the application still running. A direct accessible close in the same fixture took about **71 ms**. These are single observations, not latency percentiles.
- A separate fixture's windowShouldClose presented an NSAlert sheet. The close operation returned `confirmationRequired` in about **469 ms**, without accepting it. UI cancellation kept the target window; a second attempt followed by explicit UI confirmation closed it. Integrated panel/cache behavior after both dialog outcomes still needs the release matrix.
- A visible production PanelController with 11 fixture cards and an injected successful close showed tint/title/underline removed while the CRT point remained. Confirmed removal highlighted the next card. Grouped 11→10 and 6→5 transitions retained width **1088 pt**.
- Sampling NSWindow.frame every approximately 10 ms observed intermediate heights for 11→10: `596, 590, 580, 567, 549, 529, 508, 489, 474, 462, 455, 453, 452` pt; for 6→5: `452, 445, 433, 417, 396, 372, 347, 325, 306, 292, 284, 281, 280` pt. This proves intermediate geometry, **not display frame pacing**. The visual fixture temporarily suppressed automatic resign-key dismissal to permit inspection; the handoff resign-key path is separately regression-tested.

The regular accessory application starts, but Computer Use cannot reliably bind its windowless entry or trigger global shortcuts in this environment. Therefore native fixture buttons and direct controller calls do not constitute physical Command-D/Command-F acceptance. The normal application entry was restored and rebuilt afterward.

## Reproducible CPU benchmark

Run from this branch on the same machine, sequentially:

```sh
scripts/benchmark fe3a221
scripts/benchmark
```

Each command makes a disposable checkout, substitutes only its benchmark main, builds release configuration, and deletes the checkout afterward. Settings use isolated suites. For each case, discard five warm-ups and report 30 samples. The operation appends `w` to unchanged matching result identities, lays out, and paints the content into a bitmap; Backspace resets it between samples. P50/P95 use sorted sample indices 14/28. Previews are missing-image placeholders. No desktop capture, disk cache warm-up, actual input delivery, or WindowServer presentation is measured.

## Outstanding release gates

1. Physical shortcuts in both trigger modes; actual application focus/settings ordering; slow/unresponsive target AX timeout and cancellation, including no late activation after Escape or a replacement session.
2. Minimized, parked Stage Manager, other-Space, and available secondary-display windows; same-app siblings remain listed after reopening. End-to-end panel/cache confirm and cancel behavior for save dialogs.
3. Search long queries/rapid input, grouped and ungrouped height transitions, Reduce Motion, CRT/caret cleanup over 20 real open/dismiss cycles, and fresh login-item/permission behavior. Tests cover individual invariants, not the full native matrix.
4. Thirty-sample rendered-feedback P50/P95 for warm presentation, search and close feedback; cold disk cache and warm image cases separately; actual CRT/resize frame intervals and missed refreshes. Unavailable hardware must remain explicitly unverified.
5. After acceptance and owner merge, verify the merged commit/CI, rebuild and inspect the DMG, tag `v0.0.6`, publish DMG/SHA-256/release notes, then download and verify the asset.

The implementation PR does not authorize skipping these publication gates. See [release notes](0.0.6.md) and the specification for the final shipping contract.
